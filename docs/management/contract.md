## Process lifecycle and mounting

`runtimeManager.management *contract.ProcessServices` owns Store, Accounts, Tasks, Verifier and HTTP for the **process**. `runtimeGeneration` owns none of them. No `StartService`/`StopService` path recreates the store, Key service, task worker, identities, versions, idempotency, audit or receipts. Final startup order:

1. Open the explicit management SQLite path (planned default `runtime/management/management.db`) and construct the process account coordinator with explicit auth paths and journal directory. Do not read real paths in tests.
2. Recover credential journals using `AccountCoordinator.Recover` / `Store.RecoverAccounts`; reconcile legacy identities and credential digests before constructing/publishing an active production pool. Failure is fail-closed: no production account admission.
3. Bind a dormant generation with a unique, nonzero process epoch. Publish reconciled account state through the coordinator before accepting production leases. Hook every native writer before use.
4. Construct Tasks and call Start once; Start calls Store.RecoverTasks once after account recovery, attaches missing immutable receipts by task/item identity, and starts workers only for returned safe queued IDs. Construct the isolated verifier/target and HTTP registrar once. Populate `api.Config.Management`.
5. On generation replacement, serialize coordinator binding against outstanding account mutation leases before publishing the new generation. Do not close process management services. Shutdown closes Tasks cooperatively, then Verifier and Store once; finish committed journal cleanup safely.

Only registration seams are installed in G0. No store, scheduler, HTTP business handler, verifier or frontend is implemented or activated. A nil `Config.Management` preserves the existing configuration behavior.

`HTTPRegistrar.Handler()` receives **full paths** for exact `/api/manage/v1` and its subtree. `KeyHandler(ConsoleAuthorizer)` receives exact `/api/management-keys` and its subtree. G0 dispatches these paths before both root ServeMux path cleaning and native console authentication, including duplicate slash/dot paths; G3 must reject noncanonical paths with management JSON. Do not use redirects, HTML fallback, default ServeMux text 404/405, StripPrefix or model authentication here. Exact roots are included to avoid slash redirects. Namespace handlers own terminal JSON 404/405 and `Allow` on known-path 405. `/health`, ordinary model endpoints and native pairing remain registered as before.

The console authorizer uses the **same** existing password-login session owner as native console routes. Login disabled + loopback is insufficient. Model Key, management Key, pairing token, missing/expired/logged-out session are insufficient. G3 key HTTP checks same-origin/CSRF (including `Sec-Fetch-Site: cross-site`) and emits frozen envelopes; it must not wrap the native auth middleware whose errors have another shape. Existing sessions are password-only in this Go version; any future alternate login method must add explicit provenance before permitting Key admin.

## Wire rules

- Success is exactly `{data:...,requestId}`; asynchronous admission is HTTP 202 with `data:{taskId,status:"queued"}`. Replays return that original queued acceptance even after completion; GET the task for current status. Errors are exactly `{error:{code,message},requestId}`. Errors in a task do not change GET task's HTTP 200.
- Every management response, including malformed input, unknown paths and Key admin errors, has `Content-Type: application/json`, `X-Request-Id` equal to envelope `requestId`, and `Cache-Control: no-store` exactly. IDs are server-generated lower-case `req_UUIDv4`; ignore inbound request IDs. Normal model `newID` behavior remains unchanged.
- All public times use `Timestamp`, exactly `YYYY-MM-DDTHH:mm:ss.sssZ`; UTC, three fractional digits, no offset/floating local times. Optional times are explicit null. Zero required times are invalid.
- Use `NewError` / `PublicError`. The 21 Manager `REMOTE_ERRORS` entries have identical English messages and HTTP status in Go and OpenAPI. The additional `CONSOLE_PASSWORD_REQUIRED` is console-only, HTTP 403. Never put native error strings, raw upstream response bodies, credentials, hashes or proxy URLs into public messages. `ErrorCatalog()` returns a copy; OpenAPI contains all exact mappings.
- Lists are `{items,total,offset,limit}`, default 50, maximum 200; nonnegative offset; invalid numeric input is INVALID_REQUEST. Empty items is `[]`, never null. Each page's count and rows use one DB snapshot. Accounts sort by persistent index ascending, tasks by createdAt descending then taskId descending, audit by timestamp descending then auditId descending. Separate pages can change; callers must detect drift via bounded repeated GET scans rather than infer absence.
- All indices/versions/counts fit JavaScript safe integers. Account IDs are persisted UUIDv4 without an email or numeric index. Tasks/keys/audit/operations use `task_`, `mkey_`, `audit_`, `op_` plus UUIDv4. Never treat a token fingerprint as createdByKeyId.

## Admission order and authorization

Bearer management tokens only in `/api/manage/v1`; no console/model fallback. G3 authenticates and checks required scopes, enforces a 10 MiB body bound, rejects malformed JSON/unknown control fields, validates request shape and credential structure, then checks Idempotency-Key and admits atomically. In particular `{items:[]}` is **INVALID_REQUEST before checking a missing Idempotency-Key**, creates no task, and preserves Manager's existing preflight behavior. Oversized bodies/credentials/batches use PAYLOAD_TOO_LARGE; empty/duplicate/invalid clientRef or invalid model use INVALID_REQUEST. Enforce max 100 items, 1 MiB serialized credential value, nonempty trimmed clientRef at most 128 characters unique in batch; model uses the frozen safe alias pattern (parenthesized thinking suffixes are not accepted as aliases).

External credentials accept only accountName/cookies/origins and allowlisted Playwright cookie/origin fields, including optional partitionKey. A legacy JSON-encoded credential object is decoded and subjected to the same bounds and checks. Reject accountId/index/versions/disabled/expired/auth extensions and other controls. G2 `PrepareCredentials` validates email identity and the currently usable SAPISID + __Secure-1PAPISID + __Secure-3PAPISID signing material locally. This is not online identity or model proof. Native internal credential material can retain supported native extensions; it cannot be JSON serialized as a public result.

Scopes and templates exactly match OpenAPI. Operator excludes export/archive/settings:write/audit:read; readonly includes audit:read. Import/replace require accounts:write, and verify omitted/true additionally accounts:test. Independent test requires accounts:test. Archive/restore require accounts:archive; list/read/export/settings/usage/audit/tasks use their corresponding scopes. Task cancellation requires tasks:write. Key create/list/revoke use true console authorization, not any management scope.

Task submissions require Idempotency-Key. Persist its namespace `(createdByKeyId, key)` and digest `SHA256(method + "\n" + fullPath + "\n" + canonicalJSON)`. Canonical JSON uses schema-normalized typed values and encoding/json: sort object keys, preserve array order, normalize legacy encoded credentials to decoded values, and apply defaults consistently. Same namespace/digest returns original task; different digest is IDEMPOTENCY_CONFLICT. Queue limits/revocation/expiry are checked inside atomic admission. Admission.QueueLimit is supplied by the service (default 100 when TaskServiceOptions.QueueLimit is zero), and Store enforces it in the admission transaction. Replays of already admitted identical tasks remain readable; they must never start a new task. Keep task/idempotency records together for 30 days; receipts and identity/index tombstones outlive task pruning. Expired history or no matching task is not permission to retry an unknown-result write.

Management tokens are `mgmt_` + base64url(no padding) of 32 cryptographic random bytes. Persist only SHA256 and metadata; plaintext is returned once from create. List/auth projections contain no digest/token. Constant-time digest comparison, expiry and persisted revocation are enforced. Revoke atomically cancels queued writes and blocks new admission; running work remains attributed and committed effects survive. No model or console Key substitution.

## Identity, state and versions

Always return accountId/index/accountName/enabled/archived/expired/disabledReason/disabledStatus/disabledAt/credentialVersion/stateVersion. Optional disabled metadata is null. Native normalized email is internal identity; persisted mapping remains stable across replace/archive/restore/restart. Reserve index allocation durably before file publication; high-water allocation never moves backward, including failed creates, archived/deleted records and legacy files. Retain UUID/index tombstones. Duplicate email import rejects active or archived identities; it never replaces. Restore uses the original UUID/index and restores disabled manual state; fetch new versions before replace.

Versions start at 1. Credential replacement increments credentialVersion even if content repeats; background refresh increments it when effective credential digest changes. StateVersion increments only for actual enabled/archive/expired/disabled metadata changes. Versioned replace requires both positive expected versions. Optional legacy/native CAS is either both or neither; partial/null/zero/out-of-range pairs are invalid. Account PATCH uses `Enabled *bool` and G3 rejects absent/null, rather than interpreting `{}` as disable. Recheck both versions inside the serialized commit after verification/drain. A changed version gives VERSION_CONFLICT without a stale write.

Busy, pool saturation, worker warmup, entitlement failure and cooldown do not imply expired login. Only definitive authentication evidence sets expired/auth-required metadata. Preserve native runtime state separately through safe diagnostics. Never automatically clear a later manual/quota disable when verification, refresh, recovery or a stale upload finishes.

Initial import commits enabled before optional independent verification. `verify:false` does **zero** model calls and returns UploadOnlyResult. Versioned `verify:false` replace atomically replaces and enables while preserving unrelated newer state through dual CAS. `verify:true` replacement verifies an isolated candidate before the commit, then rechecks both versions. Legacy raw replacement verifies by default and preserves current management flags. Replacing archived accounts requires explicit restore first. Upload success is not verification evidence.

## Commit participants, leases and crash recovery

G1 owns SQLite metadata, UUID/index allocation, key hashes, tasks/private inputs, idempotency, audit, immutable upload receipt rows and commit records. G2 owns actual credential/config files, staging/backups, native runtime locks and pool/header/worker publication. G1 never invents a second credential store. `CommitAccount(ctx, intent, participant)` is their shared atomicity boundary; no network, browser, model or 60s drain wait occurs in a DB transaction or participant method.

Store returns detached snapshots/copies, including scopes, task item/result slices and receipts; callers cannot mutate live storage state through aliases. Missing GetAccount/FindAccountByNativeID/GetTask is NOT_FOUND. Missing GetUploadReceipt is `(nil, nil)`, never a fabricated receipt. Reusing a committed upload operation for a new write is INVALID_STATE; an ordinary same-submission replay is handled before execution by AdmitTask.

1. The coordinator captures native snapshot + both versions **before** network work. Acquire the generation-bound `AccountMutationLease`; it waits at most 60s for drain and continuously blocks new production leases until Release. It pins one epoch through CommitAccount and lease.Publish. Native account creation also uses this gate. Worker drain includes fingerprint writers for replacement/archive/delete; fingerprint-only maintenance does not increment credentialVersion.
2. Under a short process account/allocation gate, G1 checks dual CAS and reserves immutable mapping/index. Persist a planned record containing operation ID, before/after metadata and trusted upload identity. Never expose an uncommitted account as current.
3. With **no open SQLite transaction**, participant.Prepare durably stages new bytes and backups keyed by operation ID and returns its persistent reference. Mark prepared; Apply writes/renames safely; mark applied. Every step has durable intent before effect and recoverable file digests. Preparation can crash before returning its reference: rollback locates its private journal by operation ID.
4. After Apply, one SQLite transaction commits final metadata/digest/versions, immutable task/item receipt (when present) and committed journal marker. committedAt is captured at this successful file/metadata commit, never from a later account read. Then Finalize cleans file backups. After commit cancellation or audit failure cannot erase this evidence or roll back committed credentials.
5. Publish pool/header/worker changes using the **same lease and epoch**, outside storage locks; Release on every path. Publication failure returns durable evidence and leaves the account unavailable until reconciled. Never retry credentials just because publication failed. Lease.Release does not expose stale runtime/file views.
6. On restart, recover **before** production publication. Uncommitted planned/prepared/applied records roll back to the before image; committed records verify the applied image and finalize only. Never reapply an old committed image over a newer image. Participant digest checks refuse unexpected newer/out-of-band changes rather than overwrite them. Pending cleanup blocks a subsequent same-account commit until resolved. No recovery path calls a model, replays credentials or re-enables an account.

Lock order is coordinator bind/read gate → runtime mutation lease → management account/allocation commit gate → short participant/native storage locks; release storage/DB locks before publication. Native entry points must release any existing storageMu before entering the coordinator. Never acquire manager.mu.Lock under the coordinator or hold manager.mu.RLock across a new coordinator acquisition in final assembly. BindRuntime takes the coordinator's exclusive bind gate and waits for prior leases; it cannot redirect a lease to a new generation.

G2 must cover `AccountStore.Create`, `AccountLease.SaveStorageState`, `RefreshStorageState`, `ReplaceCookies`, `MergeSetCookieHeaders`, native enable/disable/delete/relogin, Chrome import, pairing and `setup --remote`. The ephemeral native authGeneration is not the persistent management version. Auto-refresh snapshots capture both versions before their network call. A stale normal response Set-Cookie merge may merge only into a proven unchanged credential lineage with fresh snapshot/CAS; it must discard conflicting stale cookies instead of overwriting newer replacement/manual state. A discarded opportunistic merge does not turn already successful generation into an API error. Any retry is bounded and contains no repeat network/model call.

S1 active-lease supplement: native Cookie/refresh/auth-state callbacks already own an active production AccountLease. G2 attaches its NativeLeaseProof via WithNativeLease and, while holding its bind read gate, uses the runtime's NativeMutationRuntime.AcquireNativeMutation. Validate live proof/account/epoch and retain that epoch through commit/publication. This path does not wait for active=0 or for a management drain waiting on itself; no worker reset or force-interruption of the caller's stream is permitted. Only new management/native lifecycle operations without an existing proof use full AcquireMutation drain. Account/file CAS serialization still applies to both paths. See g0-status S1 for exact new signatures.

Offline setup/direct file writing is supported only with service stopped. At next startup NativeAccount.CredentialDigest lets ReconcileAccounts increment credentialVersion for detected changed bytes and invalidate prior verification evidence, without rewriting credentials; true state changes advance stateVersion. Reconcile preserves archived/deleted tombstones and cannot infer deletion/restore from missing files. Malformed legacy files fail closed rather than being silently removed. Concurrent external/offline writers or multiple service replicas are unsupported.

## Durable tasks and immutable evidence

Task kinds are frozen as import/replace/test/archive/restore/reload/reload-auth/batch. Public tasks include stable taskId, kind, createdByKeyId, all UTC timestamps, counts, safe item status/progress/stage/clientRef/accountId/index/result/error/upload. Internal task revision, cancellation flag and private input are never public. Update with optimistic task revision; transitions cannot regress or silently replace a receipt.

Task states: queued → running → succeeded/partial/failed/cancelled/interrupted. Partial means a terminal mixed outcome, not resumable execution. Cancellation is cooperative and does not undo a commit. Item receipt attachment happens immediately after commit and before verification; a failed/cancelled/interrupted item can still have committed upload evidence. `ItemResult` is the closed union of UploadOnlyResult or PlaygroundVerificationResult, never arbitrary maps.

Receipt identity is `(taskId,itemIndex,kind)`; each receipt stores committed accountId/index/credentialVersion/stateVersion/committedAt. `GetUploadReceipt` reads the original store evidence only. Duplicate operation writes reject rather than overwrite. Never fill a historical receipt using live account versions; missing evidence, including old tasks, means unknown, not proven no upload. Later writes/archival/state changes preserve receipts unchanged.

RecoverAccounts runs first. RecoverTasks then copies original receipts into missing task items, interrupts running tasks without replay, and interrupts stale queued snapshots that already have a receipt. Only queued tasks with no execution/commit evidence are returned for resumption. Erase interrupted/terminal private inputs; retention/pruning never requires them for receipt recovery. Do not re-run verification on startup. Shutdown/cancellation must record known committed state even when the request context has already been cancelled, using a bounded cleanup context.

Audit is allowlisted metadata. Post-commit audit failure reports AUDIT_PERSISTENCE_FAILED and retains committed state; it is not a rollback proof. Other persistence failures report PERSISTENCE_ERROR with its exact warning to read current state before retrying. Store/service cannot claim no admission based only on arbitrary HTTP status or transport failure.

## Isolated Playground verification and projections

G4 takes `VerificationTarget.Open` → an isolated `VerificationSession`, supplied by a separate app adapter. Fix AccountID, native ID, model and channel=playground; do not call ordinary routed Generate or production retries, use another account, production worker or Build fallback. Candidate storage state may be refreshed only in the isolated session and returned privately for the eventual CAS replacement. The verifier never publishes credentials or changes enabled/expired/quota/manual state as a side effect.

Default verifier concurrency is 1, deadline 10 minutes, one bounded fixed prompt ("Reply with OK.") and bounded output tokens. `verify:false` never enters it. Successful model verification needs upstream 2xx, matching pinned IDs/model, actualChannel=playground, observed completion, non-whitespace visible answer and reliable identity confirmation. Empty output, thinking-only output, finish-only, missing terminal event, cancellation, deadline, wrong identity/model/channel, or raw HTTP 200 alone is not success. Connection mode uses connection_verified and is not model proof. Preserve the versions captured for the tested credential; later account changes do not rewrite historical verification evidence.

`PlaygroundVerificationResult` is a **separate closed schema** containing required actualChannel, versions and req_UUIDv4. The original closed Aitoapi `VerificationResult` remains in OpenAPI for reference and is not used for Go task results; simply adding a property through allOf would violate additionalProperties:false. Manager's new backend must explicitly preserve this extension.

System capabilities identify aistudio2api/v1 and distinguish safe capabilities. System status keeps compatible basic counters and adds serviceState/waaBackend. browserConnected can be false with a ready Go WAA backend. Settings expose only typed Go values and persistentKeys; phase one advertises settingsWrite:false and PATCH returns INVALID_STATE without mutation. No Aitoapi-only setting is fabricated. Diagnostics account entries and usage are bounded pages; no native config, Key/hash, Cookie, credentials, body, free-form logs, proxy password or URL userinfo appears in these DTOs. Actual use/capability gaps must be reported explicitly.
