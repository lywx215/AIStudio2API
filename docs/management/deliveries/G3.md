## Construction and lifecycle

```go
func NewTaskService(options contract.TaskServiceOptions) (contract.TaskService, error)
func NewHTTP(options contract.HTTPOptions) (contract.HTTPRegistrar, error)
```

Both use the frozen contract package. Store/Accounts/Verifier are required for the task service; Store/Accounts/Tasks/Projection are required for HTTP. Nil Clock/NewID use time.Now/contract.NewID. Default queue limit is 100; positive QueueLimit is copied to Admission and atomically enforced by Store. The worker is serial; upstream waits occur after Store methods return, outside transactions.

G0 must recover accounts before calling `Tasks.Start(processContext)`. Start itself calls `Store.RecoverTasks` exactly once, then schedules only returned safe queued IDs. Repeated Start is idempotent; Start after Close is rejected. Close cancels active work and records interruption while preserving receipts; unclaimed queued tasks remain durable for the next process. G0 closes Verifier/Store after Tasks.Close. This service does not own generation starts/stops or close its collaborators.

`HTTP.Handler()` accepts full `/api/manage/v1` paths. `KeyHandler(ConsoleAuthorizer)` accepts full `/api/management-keys` paths. G0 supplies the real password-session authorizer; G3 never accepts loopback login bypass, model Key or management Bearer as console authorization. Key writes require `X-Requested-With: XMLHttpRequest`; cross-site/same-site Fetch Metadata and mismatched Origin are rejected. Key token creation/hash persistence/authentication/revocation stay in G1; only typed key DTOs are emitted.

All frozen management endpoints are implemented, including capabilities/diagnostics and synchronous PATCH/export. Actual readiness/capabilities/settings/usage come only from G0's injected Projection. Empty readiness is HTTP 200 with ready:false; unsupported settings writes return INVALID_STATE. No native config, proxy credentials or fabricated usage/capability success is serialized.

### Owned implementation

- `http.go` copies only the original explicit CAS pair into trusted `Admission.Capture.Expected`; the kind determines capture mode. Existing HTTP request/response formats, errors, canonical normalized body and digest stay unchanged. No server snapshot is added to the private body or fingerprint.
- New `preconditions.go` validates the durable format/mode/count manifest and per-item mapping before execution. Only legacy import may omit the manifest. Missing targets return NOT_FOUND without rebinding; otherwise both the observed admission versions and original client pair must pass `TaskPrecondition.Check`. Explicit future versions cannot become valid merely because live versions later catch up. Safe migrated legacy explicit-CAS replace is accepted only with the frozen unknown-snapshot row and original pair.
- `orchestration.go` checks stale replace/test/archive/restore/reload/batch before any collaborator action. Replace retains effective frozen CAS through isolated verification and commit; state commands receive detached `precondition.Expected()`, including force requests. SnapshotCredentials UUID/versions are checked again before verification. A stale batch item reports VERSION_CONFLICT while other items continue.
- reload-auth pages only its fixed immutable admission table, checks claimed count and contiguous ordinals, and never calls ListAccounts while executing. It supports more than 200 targets and an explicitly captured empty set. Later new accounts are absent from the target set; changed targets conflict, and the remaining fixed targets continue. Public aggregate shape is unchanged.
- New `scheduler.go` replaces the pending-ID slice with bounded, oldest-first database keyset scans. Wake is a hint; a durable task is discovered even after admission commits but its response reports persistence failure. Each scan uses limit200 and advances the keyset so an old bad row does not hide later queued tasks.
- Failed Claim is read back with a bounded cleanup context: confirmed queued retries after 200ms, 400ms, 800ms, 1.6s, 3.2s, then at most 5s; ambiguous running before business is interrupted without execution; terminal is skipped; read failure retains an unresolved readback-only hint. The map is bounded to 200 unresolved attempts. A successful claim / started business can only be read/finalized afterwards and never claimed or executed again after an uncertain state write. RecoverTasks is still called exactly once by Start, never for runtime retry.
- `tasks.go` validates persisted private operation shape before business; malformed JSON/controls such as a missing batch action interrupt instead of falling through to disable. Existing cancellation, original receipt readback, cleanup and public task projections are retained. Close cancels and joins this worker and stops its idle/backoff timer.
- **Prune ownership changed by explicit dispatcher handoff: G0 exclusively owns the immediate/hourly/30-second maintenance timer and join-before-Store.Close. G3 adds no Prune loop or second timer and never closes Store.** The earlier preparation text proposing G3 maintenance is superseded.
- Tests: updated owned `http_test.go`, `tasks_test.go`, `test_helpers_test.go`; added `queue_safety_test.go` and `scheduler_test.go`. No other owner's file, global ledger, public contract, branch or worktree was edited/created.
