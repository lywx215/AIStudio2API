## 实施设计与交接点

- `app/management_accounts.go` 提供冻结构造 `newManagementAccountCoordinator(contract.AccountCoordinatorOptions)`，进程级持有 Store、bind gate 与提交/发布 gate。`aistudio/management_account_files.go` 提供共用可恢复文件 participant，`management_account_native.go` 提供原生门/快照/三方 Cookie 合并。
- 文件 participant 以 operation ID 建私有日志，Prepare 同时记录 before/after 摘要及完整恢复材料；Apply/Rollback/Finalize 幂等，拒绝覆盖不符摘要的后继文件。归档保留原始身份和目录，restore 恢复为停用；删除保留 Store 墓碑。
- G0 负责在生产池开放前 Recover、绑定非零且唯一 epoch 的 runtime、给 AccountStore/AccountPool 注入 native writer；generation 切换必须在 bind gate 外释放 manager.mu，防止锁反转。
- 原生 RefreshStorageState 已先捕获持久双版本与快照，释放文件锁后执行网络刷新，再进入共同门提交，成功后推进本租约快照；不沿用旧实现跨网络持有 storageMu 的方式。
- Set-Cookie/ReplaceCookies 已使用独立持久版本快照和受控 lineage 合并；丢弃 stale opportunistic merge 时保留已成功请求结果。
- AccountStore.Create、Delete、SaveConfig、认证过期状态、原生登录/Chrome/配对及 setup --remote 已接入共同门；原生 Create 不在已提交管理身份后因后续错误暗中删除账号。

## G0 装配接口（已实现）

- `AccountStore.SetNativeWriteCoordinator(writer, journalDir)`；`AuthPaths()`；`NativeWritesCoordinated()`。
- `AccountPool.SetNativeWriteCoordinator(writer, paths, journalDir)` 及 `SetManagementEpoch(epoch)`，均在 generation 发布前安装，运行期不变更。
- `AccountLease` 实现 `contract.NativeLeaseProof`；真实 Release 原子使 Active=false。原生提交经 WithNativeLease 固定 epoch，通过 G0 NativeMutationRuntime.AcquireNativeMutation；不等待自己的 active lease。
- `AccountPool.AcquireManagementAccount(ctx,id)` 不递归获取 coordinator snapshot；管理替换/归档/删除继续完整排空与 worker 指纹排空。
- `AccountDirectory`、`LoadAccountDirectory`、`CredentialDigest`、`PublishManagementAccount(record,preserveLineage)` 供 G0 runtime 组合。Publish 不进行网络/模型动作。
- 原生创建/登录指纹与凭据放入同一恢复日志，避免提交后直接删除身份作为错误清理。普通后续 catalog 失败不删除已提交账号。
- coordinator 的 gate 从 Store.CommitAccount 持有到 lease.Publish 返回，DB/文件短锁在 Publish 前已释放。防止 A commit v2 → B commit v3 → A Publish(v2) 的旧摘要/旧状态发布。
- BindRuntime 使用 TryLock 等待，不排队阻塞 native 读门；否则“管理排空等待 active + Bind 写者等待 + active native 写入读门”会形成死锁。
- 原生 authCheckedAt 即使 expired 不变也更新；账号级 authStateMu 使观察顺序与持久 CAS 有序，只允许同 credentialVersion 的认证字段重基，不清除 manual/archive 状态。
- 专用 authRefreshMu 跨租约去重网络续签；等待完成后在网络前重新捕获双版本，网络不持有 storageMu/pool.mu/管理提交门/DB 事务。
- 正常 Cookie 响应使用 base/incoming/latest 三方合并；同字段的新旋转保留，独立字段可合并；旧 epoch、已删除/归档/停服或新人工状态的机会式回写丢弃，不把成功模型调用改成失败。真实持久化失败仍返回错误。
- import 重复身份先预检，再由 Store 原子复查；重复 archive 不制造 disabledAt/stateVersion 变化。restore 原 UUID/index 且停用；双 CAS 在排空后由 Store 重新检查。
- `SnapshotCredentials` 在共同门内核对实际文件与持久摘要；Prepare 再验证 before 摘要/原生身份，拒绝 out-of-band 新文件。已提交 Publish 失败保留原 receipt，不重复写凭据。
- 离线 setup/直接文件工具仅在停服时使用；`setup --remote` 经原生 import/addAccount 走协调器。外部并发直写/多副本不在支持范围，恢复遇到未知映像会 fail closed。
- 硬删除将整个账号目录原子 rename 到原目录同一父目录的 `.account-delete-<op>.tmp`，不复制或漏掉 Camoufox 嵌套缓存，也不要求 AuthPaths 与 JournalDir 同 volume。Prepare 记录日志先于 rename；未提交恢复移回原目录；DB 提交后只清理该备份，保留原 UUID/index 墓碑；清理中断可重复 Finalize，原目录出现新图像即拒绝覆盖。
- 原目录/备份目录均通过配置来源绝对路径映射与 operation ID 派生值核对；每阶段拒绝路径祖先及缓存树中的 Windows reparse / symlink。`RemoveAll` 只接收已校验的固定兄弟备份路径，不使用 JournalDir 作为跨盘移动目标。
