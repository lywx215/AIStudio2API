## 提交与恢复接口约定

1. `CommitAccount` 的进程串行门覆盖 CAS、分配、日志和文件参与者；**所有** `Prepare/Apply/Rollback/Finalize` 调用在 SQLite 事务外。SQLite 只有短事务。
2. 身份和 planned 日志先持久化；Prepare 即使在返回 participantRef 前崩溃，也以 `OperationID` 恢复。失败分配的 identity/index 保留，不给其他邮箱复用；删除保留 tombstone。
3. Apply 后在同一事务写最终 After、原始 receipt 和 committed journal。receipt 的 `status` 是 `committed`，时间在该事务边界取值。DB commit 返回不确定错误时先以独立有界清理 context 读取持久 journal：未 commit 才 rollback，已 commit 仅返回原证据并 Finalize。
4. Finalize 或日志清理失败保留 pending log，阻止下一个同账号写入；`RecoverAccounts` 对未提交记录 rollback，对已提交记录只 Finalize，不重放 Apply。清理完成后日志仍留存，保证 OperationID 不会被重新写入。
5. `AccountCommitResult.Published` 保持 false，由 G2 持有同一个 mutation lease 进行实际运行池发布后设置。Store 不伪造发布成功。
6. `RecoverAccounts` 必须先于 `RecoverTasks`。后者拒绝未解决的账号日志，从 receipt 表附回原证据，running / 已有提交或尝试证据的 queued 均 interrupted；只返回没有执行证据且有私有输入、Key 有效的 queued ID，不执行账号/模型动作。
7. 终态或取消请求清除 `task_inputs`。`Prune(ctx, cutoff)` 把 cutoff 限制为最迟 `Clock()-30d`，仅清理过期终态任务、对应幂等和审计；receipt、identity/tombstone、提交日志保留。

## 已编写测试的覆盖范围

- planned、Prepare 中途、Prepare 返回未记录、prepared、Apply 中途、Apply 返回未记录、applied、metadata 写入、receipt 写入、DB commit 前后、Finalize 中途及返回后重启。
- 事务内故障回滚；commit 后取消仍保留回执并完成清理；文件参与者用单 DB 连接/有界查询证明事务外执行。
- Finalize 失败阻止后续写入；重复 OperationID 只读原回执，不再 Apply；SQL 拒绝修改/删除 receipt。
- 并发双 CAS 只有一个成功；旧状态版本不能覆盖更新的人工禁用；重复内容 replace 仍递增 credentialVersion；refresh 相同摘要不递增；archive/restore 保留 UUID/index/人工停用。
- 失败创建、删除和重启后的 index 高水位与身份墓碑；离线摘要 reconcile。
- Key 只存摘要、过期/撤销跨重启；撤销与 24 个并发 admission 的竞态；queue bound。
- 同幂等正文返回最初 queued ack，即使任务已终态；不同摘要冲突；不同 principal 独立；空 items 优先 INVALID_REQUEST。
- clientRef 与 G3 一致：非空、不允许首尾 Unicode 空白、按 Unicode codepoint/rune 计数至多 128、逐字身份唯一性，不裁剪或重写引用。新增中文 128/129 字符、首尾/纯空白、空串、中文重复及不同引用共 9 个子用例。
- SQL 页排序、空数组、limit 验证；task revision/进度/回执伪造拒绝；错误信息安全投影及私有输入清理。
- 重启后仅安全 queued 可恢复；已有回执保持原版本，即使 live account 版本较新；保留期不能被提前缩短，task pruning 不删除 receipt/tombstone。

### 文件与行为

- 新增 `migration.go` / `migration_v2.sql`：新库为 v2；真实 v1 库事务升级，失败回滚 DDL 与 user_version；>2 拒绝。迁移不读账号版本、不改旧 public task/幂等/receipt，不做执行恢复；startup RecoverTasks 在账号恢复后才作兼容决策。`testdata/schema_v1.sql` 保存变更前真实 v1 DDL，测试并非仅改版本号冒充旧库。
- 新增 `preconditions.go`：新 admission 必须携带匹配 kind 的可信 Capture。原始幂等命中先返回原 queued ack，不因 live 版本/归档/删除或 queue full 改变；仅新任务在同一 admission 事务中保存 immutable preconditions、format=1 completion manifest、原 private input、原 digest/ack。已知缺失目标保存 Missing=true、NULL 版本，绝不执行时重新绑定。
- 显式 ClientExpected 与 observed snapshot 分别保存。即使 client expected 与入队版本不一致仍受理，由 G3 按两者异步 VERSION_CONFLICT；后来恰好达到原未来 expected 不能消除原 observed-snapshot 冲突。snapshot 不进入 CanonicalDigest，也不改写 private body。
- reload-auth 在 admission 事务内每页至多 200 读取非删除账号，排除当时归档项，包含 disabled；按持久 index 固定全部目标。测试实际覆盖 404 个目标、后续新增账号、后续 state 变化及 N=0 空集合。Claim 对 reload 返回空 Preconditions 和非空 manifest；`ListTaskPreconditions` 按 Ordinal 有界分页，不 join/filter live account。
- `ListQueuedTasks` 是只读、有界 `(created_at,task_id)` 升序 keyset 查询，最多 200，取 limit+1 判定 Next；空 Items=[]。查询不执行恢复或改变 running task。
- `tasks.go` 的 Claim 检查私有输入存在/合法 JSON、执行证据及完整 manifest/目标行。可证明永久坏状态持久 interrupted 并删除私有输入；保留原 receipt。暂时数据库错误仍报 persistence，由 G3 按 DB readback/rediscovery 处理；不在调度期调用 RecoverTasks。
- 新增 `recovery.go`：startup-only，v1 import 可安全保护，单个已知 UUID 且旧 privateInput.expected 为完整正数双版本的 replace 生成 SnapshotKnown=false、只保留原 ClientExpected 的保护；不读取 live account。其他旧 queued 或不完整/错配保护 interrupted；running/已有尝试或提交证据继续 interrupted。未变化终态不 UPDATE task/revision/timestamp，仍可单独擦除残留 task_inputs。
- 为防止**新 v2 任务丢失全部 manifest/rows 后被降级为 legacy explicit-CAS**，额外内部 `task_legacy_queue` 仅在 v1 迁移事务中记录原 queued 身份。旧版兼容须有此来源标记，保护成功后消费标记；新 v2 task 不产生该标记。它仅有 task_id FK、随 task 清理，无账号/凭据/公共字段。新增测试证明“丢失 v2 snapshot + 当前版本后来达到原 future expected”仍 interrupted，不能恢复执行。
- 新增 `prune.go`：沿原 Prune(ctx,cutoff) 签名，clamp 至 30 天，并以 `MaintenanceTimeout=30s` 为单轮上限。每个短事务至多处理 `PruneBatchRows=100` 的一种记录；大 precondition 集合先按 child row 分批，再删除没有 child 的过期终态 task，避免级联大事务。运行/queued 不删；receipt、identity/tombstone、account journals 完全不进入清理。context 取消保留已提交批次，剩余下轮继续。**G1/G3 不创建 timer**；定时调度与 close/join 顺序由 G0 独占。
